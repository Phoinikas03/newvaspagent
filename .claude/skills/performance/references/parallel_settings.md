# VASP 并行参数速查表

本文件供 `vasp-performance-tuning` skill 在需要时读取。这里给的是**推荐起点**，不是绝对最优值。

## 1. CPU-only 场景

| 场景 | 推荐起点 | 说明 |
|---|---|---|
| 8 核以内单节点 | `NCORE = 2` 或 `4` | 小任务避免过度拆分 |
| 16–32 核单节点 | `NCORE = 4` 或 `8` | 最常见稳妥默认 |
| 48–64 核单节点 | `NCORE = 8` | 常见起点 |
| 超大核数 CPU 节点 | `NCORE = 8/12/16` | 需结合 socket/NUMA 结构 |

CPU-only 场景下：

- 通常先试 `NCORE`
- 不要默认再写 `KPAR`
- 若用户明确做 k 点并行，再考虑加 `KPAR`

## 2. GPU 场景

| 设备使用方式 | 推荐 `KPAR` | `NCORE` | 说明 |
|---|---:|---|---|
| 单任务，1 GPU | `1` | 不写 | 最稳妥默认 |
| 单任务，2 GPU | `2` | 不写 | 适合 k 点较多静态/HSE |
| 单任务，4 GPU | `4` | 不写 | 常见多卡 benchmark 起点 |
| 单任务，8 GPU | `8` | 不写 | 需确认 k 点数足够 |
| 多任务并发，每任务 1 GPU | `1` | 不写 | 不要误设成 `KPAR = 总GPU数` |

GPU 场景下：

- 默认优先 `KPAR ≈ GPU 数`
- 默认删除或不写 `NCORE`
- 如果旧 `INCAR` 留着 `NCORE` / `NPAR`，通常应清理

## 3. HSE / 杂化泛函的经验规则

对于 HSE、PBE0、EXX 等昂贵任务：

- 多 GPU 下优先试 `KPAR = GPU 数`
- benchmark 时可固定其它参数，仅扫描 `KPAR`
- 若用户目标是“性能测试”，允许在说明中注明 benchmark 口径后再适度降低 `ENCUT` 或限制电子步数
- 若用户目标是“生产计算”，不要借性能优化随意降低物理精度参数

## 4. 何时删参数

以下情况通常应该删去旧参数：

- 用户从 CPU-only 切换到 GPU
- 旧 `INCAR` 中存在 `NCORE`，但现在要做 GPU benchmark
- 旧 `NPAR` 来源不明，且当前没有明确保留理由

## 5. 建议输出模板

当你按本 skill 修改 `INCAR` 时，优先用类似下面的说明结构：

1. 用户设备：例如“单任务使用 4 张 GPU”
2. 修改项：例如“删除 `NCORE`，设置 `KPAR = 4`”
3. 原因：例如“GPU 任务优先按 k 点并行，避免旧 CPU 并行参数干扰”
4. 未改项：例如“未改 `ENCUT/KSPACING`，因为它们影响物理结果而非仅影响性能”
